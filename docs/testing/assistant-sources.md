# DOC01: establish the actual assistant sources

Inspect the aligned installation read-only before describing its chatbot
integration. Historical Home/shared-assistant paths and metadata do not prove
the current deployment has the same sources or app guides.

1. Identify the actual AiiDAlab-level assistant package, import path, revision,
   configuration and documentation roots. Check whether retrieval reads nested
   Markdown directories or only immediate files.
2. Inspect the installed `aiidalab_assistant.workflow_guides` entry points where
   that contract exists. Record the app identity, provider, guide ID/source and
   content hash. An app repository's `docs` directory alone is not registration.
3. Inspect the actual Surfaces and QE postprocessing launchers/manifests for an
   embedded assistant. Do not promise a panel or tool that is absent. Keep an
   unrelated CDXML/ORCA handoff route distinct from workflow assistance.
4. Map verified app-owned documentation to the actual retrieval route. Mark a
   missing provider, unconfigured route or unsupported integration explicitly.
   Prepare concise source-backed content without silently changing discovery,
   indexes, credentials, configuration or scientific state.
5. Later, after the manual campaign starts, ask each available assistant the
   same concrete workflow questions independently. Record its exact answer,
   cited source/revision and discrepancies. No calculation submission or remote
   action is part of this help check.

Useful source topics are listed in [DOC01](help-review.md). Keep preparation,
scientific review, actual GUI help, retrieval integration and answer quality as
separate dimensions in the [report](report-template.md).
